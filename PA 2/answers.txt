1. Counting

P(n, k) = P(n-1, k) + P(n-1, k-1)
P(n, 0) = 1
P(n, k) = 0 if n < k

Method 1 always checks 2^20 = 1048576 integers.
k = 1: 1048576 / 20 = 52429 per portfolio
k = 5: 1048576 / 15504 = 67.6 per portfolio
k = 10: 1048576 / 184756 = 5.7 per portfolio

Method 1 is closest to the other two at k = 10. C(20, k) is biggest in the middle, so that is when the fewest integers get thrown away.

2. Gosper's hack

x = 01110
c = 00010
r = 10000
r ^ x = 11110
(r ^ x) >> 2 = 00111
00111 / 00010 = 00011
next = 00011 | 10000 = 10011

Line 1 isolates the lowest 1 bit of x. ~x + 1 is -x, which matches x only at the lowest 1 bit.
Line 2 adds that bit, so the carry goes through the lowest run of 1s and lands in the 0 above it.
Line 3 takes the bits that changed (r ^ x), drops two of them with >> 2, slides the rest down to bit 0, and ORs them back in. That puts the leftover 1s at the bottom so the result is the smallest next number with the same bit count.

Dividing by c is a shift because c is a power of two. x / 2^t is the same as x >> t. We use division because we don't know t, we only have the mask c.

3. Work per portfolio

(a) Each level of get_portfolios copies its results into a new vector, and the recursion is at most n deep, so a portfolio gets copied at most n times (20 for n = 20). Gosper's hack would be fastest for big inputs since it does constant work per portfolio with no recursion and no copying.

(b) variance_all_pairs always checks n^2 = 400 pairs. portfolio_variance checks k^2: 4 pairs for k = 2 and 100 pairs for k = 10.

4. Scaling

Method 1 would check 2^40 = 1099511627776 integers.

With n = 40 the unsigned int only has 32 bits, so 1u << n is undefined and stocks 32 to 39 have no bit. Main already rejects n > 31. Also storing 847660528 portfolios in a vector would take over 3 GB.

Gosper's hack can do it without storing anything. Keep only the current x and the best so far, compute the variance, call next_portfolio, and stop when x reaches 1 << n. It just needs a 64-bit integer.

5. Correlation

5 least volatile: DUK SO PG KO JNJ (14.0%)
Lowest-risk: DUK PG JNJ MSFT XOM (11.2%)

The lowest-risk portfolio holds MSFT (rank 13, 28.9%) and XOM (rank 10, 24.9%) instead of SO and KO.

Portfolio variance adds up cov[i][j] over every pair, not just each stock's own variance. The 5 least volatile stocks are all defensive and move together, so their covariances are big. MSFT and XOM are more volatile on their own but barely move with the other stocks, so their covariance terms are small or negative. Swapping them in lowers the total even though their individual variances are higher.
